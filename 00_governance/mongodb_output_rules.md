# MongoDB output rules

Source: owner's requirements of 11 October 2026.

## 1. MongoDB shell output (sample documents, seed .js files)

| BSON type | Write as | Example |
|---|---|---|
| Date (tag Date) | `ISODate("YYYY-MM-DDT00:00:00.000+0000")`, local calendar date | `ISODate("2026-10-08T00:00:00.000+0000")` |
| Date (tag Datetime) | `ISODate("YYYY-MM-DDTHH:mm:ss.sss+0000")`, local plant time (IST) | `ISODate("2026-09-15T06:00:00.000+0000")` |
| Int32 | `NumberInt(n)` | `NumberInt(240)` |
| Int64 | `NumberLong("n")` | `NumberLong("1250000")` |
| Double | `Double(n)`, also for whole numbers | `Double(18)`, `Double(18.5204)` |
| Decimal128 | `NumberDecimal("n")` with the value as a string, so no binary rounding occurs | `NumberDecimal("14.20")` |
| Boolean | `true` / `false` | `true` |
| String | double-quoted text | `"In Progress"` |
| null | `null` | `null` |

- Constructors are executable and are never placed inside quotes.
- IDs, booleans, nulls, text and dates match the collection specification exactly: type, requiredness, status values and reference rules.
- Dates are never written as strings.
- Times are written as local plant time (IST) with the `+0000` suffix and are never converted to UTC (DATA-004). A value with `T18:30:00` that stands for local midnight is an error.

## 2. Other output formats

- BSON files (`06_seed_data/bson`): native BSON types, written with the `bson` package; one file per collection named `<collection name>.bson`, concatenated documents (mongodump format).
- Extended JSON (`06_seed_data/extended_json`): canonical Extended JSON v2 (`$date`, `$numberInt`, `$numberLong`, `$numberDouble`, `$numberDecimal`).
- JSON Schema validators: `bsonType` names `string`, `date`, `int`, `long`, `double`, `decimal`, `bool`, `null`.

## 3. Sample documents

- Every collection has exactly 10 sample documents, in `03_design/<module folder>/samples/<collection name>.js`, written as one `insertMany` in MongoDB shell style.
- The documents follow the collection specification exactly: same keys in the same order, same BSON types, no added or removed keys, flat.
- All sample documents belong to one sample-data universe: an ID always carries the same display value, and every reference points to a sample document that exists. The universe is listed in `04_reference_data/sample_data_registry.md`.
- Sample dates lie between April and September 2026; shop-floor events lie in the production fortnight 15 to 26 September 2026. All are local plant time; Date-tagged keys are at 00:00:00.
- The samples are generated by `05_generator/gen_samples.py` and checked by the same run; the result is `08_validation/reports/sample_data_validation.md`. A field that seems to be missing from a specification is reported there under "Schema Observation" and is not added to the documents.
